# Тулченджеры S300–S600: перевод логики на расширение zbolt_toolchanger

Дата: 14.08.2026. Контекст для того, кто продолжит работу.

Затронуты профили: `S300 HT Dual v2.2`, `S310 HT Dual v2.2`,
`S400 HT Dual v3.2`, `S600 HT Dual v3.2`.

## Зачем это было сделано

Логика тулченджера жила в макросах, размазанных по `tools.cfg`,
`homing.cfg`, `parking.cfg` и файлу переменных. Датчики парковок читались из
Jinja через `[gcode_button]`.

**Корень проблем.** Jinja разворачивает шаблон в момент постановки команды в
очередь, а хост опережает машину на всю глубину очереди движений Klipper
(`buffer_time_high`, по умолчанию 2 с). Поэтому макрос читал состояние
датчика **до того**, как слайдер физически доезжал. Компенсировали слепой
задержкой `G4 P2000` в `T0`/`T1` — она примерно равна глубине буфера, но
гонку иногда проигрывала, и голова била в парковку.

Правильное решение — читать датчики в Python после `toolhead.wait_moves()`,
то есть синхронизировав хост с реальным положением. Никаких задержек в
g-коде для синхронизации быть не должно.

## Что изменилось в конфигах

| Было | Стало |
|------|-------|
| `klipper-config/tools.cfg` — ~14 макросов | `klipper-config/zbolt_toolchanger.cfg` — три секции расширения |
| `klipper-config/parking.cfg` | удалён, `[gcode_button]` переехали в секции инструментов |
| `homing.cfg` — «простыня» if/else | `[homing_override]` с единственной строкой `TOOLCHANGER_HOME` |
| `toolchanger-settings.cfg` | `variables.cfg` (как у одноголовых) |

Удалены макросы `T0`, `T1` (их регистрирует расширение), `_PARK_EXTRUDER*`,
`_GET_EXTRUDER*`, `_PUSH_EXTRUDER*`, `_jerk_extruder*`, `_SOL_ON/_OFF`,
`CHECK_PARK0/1`, `_START_CHECK0`, `PARKING_STATE`, `HOMING`,
`_CHECK_PARK_HOME`, `Zoffset`, `_GT1`. Для кнопок KlipperScreen оставлены
тонкие алиасы `Zoffset` и `PARKING_STATE`.

Из файла переменных убраны парковочная геометрия и служебные флаги
(`t0x_park`, `speed_fast`, `start_check`, `t*parking_state` и прочие) — всё
это теперь в конфиге расширения. Остались офсеты.

### Траектории воспроизведены один в один

Координаты перенесены из `toolchanger-settings.cfg` каждой модели значение в
значение; `safe`-точки, которые раньше считались в макросах как `park+55` /
`park−25`, записаны числами. Есть тест, который сравнивает движение,
генерируемое расширением, с раскрытием старых макросов — **16/16 траекторий
совпадают** (4 модели × 2 инструмента × парковка/захват).

Различия моделей ушли в параметры: S300/S310 — сцепка соленоидом
(`[output_pin sol]` сохранён), буст тока ×1.5 на захвате; S400 — защёлка,
буст ×1.6 **на парковке**; S600 — защёлка без буста (там `tmc5160`, а не
`tmc2209`).

## Три Z-параметра — их легко перепутать

| Что | Где | Кто меняет | Смысл |
|-----|-----|-----------|-------|
| `z_offset` в `[probe]` | `bed.cfg` | системный, не трогаем | Смещение датчика относительно сопла |
| `z_adjust` | `variables.cfg` | оператор через `SET_GCODE_OFFSET` | Подстройка первого слоя, **общая для обеих голов** |
| `t1_z_offset` | `variables.cfg` | `TOOLCHANGER_CALIBRATE_OFFSET` | Разница высот между головами |

Итог: на T0 применяется `t0offset + z_adjust`, на T1 — `t1_z_offset +
z_adjust`.

Переменная общего офсета раньше называлась `offset_z`, а на части машин —
`z_offset`, что путалось с `z_offset` у `[probe]`. Переименована в
**`z_adjust`**. **При выкатке на машину, где она ещё называется по-старому,
обязательно переименуйте ключ в файле переменных**, иначе подстройка
обнулится:

```
offset_z = -0.13   ->   z_adjust = -0.13
```

Обёртка `SET_GCODE_OFFSET` в `bed.cfg` больше не считает дельту сама — она
зовёт `TOOLCHANGER_SAVE_ADJUST`, потому что расширение знает офсет активной
головы. Старая формула на второй голове утаскивала в общий офсет ещё и
`t1_z_offset`. Отдельный `delayed_gcode` восстановления офсета убран:
единственный владелец офсета — расширение, оно применяет полный офсет той
головы, что стоит на слайдере, при старте.

## Состояние по машинам

| Модель | Конфиг в репозитории | Выкачено на принтер |
|--------|---------------------|---------------------|
| S400 HT Dual | синхронизирован **с машины** | да, проверено на железе |
| S300 / S310 / S600 HT Dual | мигрирован | **нет** |

**S400 проверен на живой машине**: хоминг из всех трёх состояний покоя,
смены инструмента в обе стороны (стабильно 6.5 с вместо прежних 8.5 с),
реакция датчиков в реальном времени, калибровка офсета, двухцветная печать с
восемью сменами инструмента без единой аварии.

**Перед выкаткой на S300/S310/S600 сначала снимите конфиг с каждой машины** —
на S400 профиль в репозитории отставал, и слепая заливка затёрла бы
калибровки. Проверьте: имя переменной общего офсета, координаты парковок,
наличие обёрток вокруг `T0`/`T1` (на S400 это были `UNSKEW`/`SKEW`).
